# Open decisions

- Local Keycloak was selected and implemented: code/PKCE browser sign-in, verified email, opaque sessions, local-mail recovery, invitation issuance/redemption and logout. Before external beta, choose hardened production Keycloak versus a managed deployment, real mail delivery, MFA/operator policy and immediate global/back-channel revocation. Current app sessions are bounded to token expiry (15 minutes in the local realm).
- Approve hosting/data region, workplace-data handling, retention/deletion and backups before external use.
- Confirm branding; “Workroom” is a reversible local UI label, not a cleared product/domain name.
- Before beta: restricted database traffic role and RLS, production invitation/operator controls, security headers/TLS, dependency audit and backup/restore drill.
- M1, M2 paste → proposal → review/approval and task-scoped guidance/reviewed updates are implemented and locally verified. Six server-configured AI adapters share explicit consent, daily limits, durable invocations and existing approval boundaries. The user supplied keys and model/rate/upstream settings are filled as of 27 October; see `docs/ai-model-configuration.md`. Real account acceptance and processor/retention policy remain pending. Configuration readiness is not vendor verification. Bounded TXT/Markdown/plain EML intake works; PDF/Word/OCR, scanning, object storage and file lifecycle controls remain next intake work.
- Then follow M2 intake/review, M2A consented model continuity, M3 reports/admin, M4 goals/reminders/PWA. Current bounded history and configured model labels do not implement continuity/checkpoints. Server key files or the explicitly selected ignored AI `.env` are local operator configuration; encrypted multi-user BYOK, retention/deletion and provider-account billing reconciliation remain unimplemented.
- PostgreSQL native timestamptz conversion is required before beta; current UTC ISO strings are a documented first-slice default.
- OpenAI currently returned 429 for two real attempts. Existing records cannot distinguish account quota from throttling because the prior mapper discarded upstream codes. New errors distinguish recognized billing/credit/usage restrictions; account billing and limits require operator review before another consented request. No automatic retry or provider switch is enabled.

- The floating Workroom AI concept from `README (2).md` is implemented locally, including provider selection and request-specific consent. Page snapshots use loaded task data; conversational workspace reasoning and generated checklist/deliverable proposals remain future functionality.

- Review of commit 73c81e7 (decisions deferred, not defects): (1) the sign-in throttle keys on the connecting address, so a deployment behind a reverse proxy needs a deliberate trusted-proxy setting or all users share one bucket; (2) capture drafts stay in browser `localStorage` for crash recovery and are removed only on explicit sign-out, so choose between recovery and clearing on session expiry or shared devices; (3) the SPA host still needs its own CSP/TLS headers, since the API now sets only API-scoped headers; (4) the oversized `create_app`, `install_*` and `oidc_callback` functions and the large `main.tsx`/`Capture.tsx` files remain a planned refactor; (5) workflow actions are pinned by tag, not commit SHA.

- Fonts (DM Sans, Manrope) are loaded from Google Fonts at runtime through the `@import` at the top of `apps/web/src/styles.css`, so every page view contacts a third party. Before beta, decide whether to self-host the fonts (also better for the privacy stance and offline use).
- Design system: tokens for color and elevation are in place (`docs/design-tokens.md`); the type scale, spacing scale and shared components are planned next. Dark mode is not planned yet, but the role-based tokens make it a small follow-up.
