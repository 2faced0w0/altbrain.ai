# Server-configured AI with reviewed proposals

Accepted locally, 26 October 2026. The user selected OpenAI, Gemini, Mistral, Grok, OpenRouter and DeepSeek. All six have selectable adapters; the deterministic mock remains available and is the current default. No real credentials, model IDs or rates were provided, and no paid model call was made. Configuration readiness does not verify account access or model compatibility.

## Processing boundary

Keys are loaded only by the API from separate ignored local files, explicit process AI variables or the root `.env` selected by the local launcher through `WORKROOM_AI_ENV`. The `.env` parser reads allowlisted AI settings only, does no shell expansion, ignores blanks and never prints values. Process variables override `.env`, which overrides JSON/key-file configuration. Tests and other entrypoints do not implicitly read the root file. The browser receives provider labels, configured model IDs, readiness and the current owner's daily usage, never secrets. There is no browser BYOK store or public configuration endpoint. This is operator configuration for a local application, not an encrypted multi-user credential vault.

Each external request needs explicit consent for the selected provider and, for OpenRouter, the configured upstream. Changing content, provider or conversation resets consent. File upload itself is local; only bounded extracted text is sent after review is requested. Task requests include the selected task snapshot, bounded notes/steps and recent conversation history. No other workspace is accessible. All source text, history and task content is treated as untrusted model input. No tools, browsing, arbitrary URLs or provider-controlled task IDs are supported.

OpenAI and Grok use Responses with strict structured output, storage disabled and truncation disabled. Gemini uses native generateContent with JSON MIME output. Mistral, DeepSeek and OpenRouter use their chat APIs in JSON mode. All outputs must still pass the existing strict server schemas, literal source-evidence checks and task-update allowlist. Provider output never directly edits a task. Capture proposals and task updates retain explicit review, optimistic task-version checks, atomic events and idempotent approval. Ambiguous/generated dates require manual exact-date input; checklist/deliverable mutation remains unsupported.

Fixed HTTPS endpoints, no redirects, bounded input/output/response bytes, timeouts and no automatic retries apply to every adapter. OpenRouter requires an explicit upstream slug, `only`, `allow_fallbacks: false`, `require_parameters: true`, `data_collection: deny`, and configured maximum input/output rates. A failed provider never silently sends data to another provider. A model alias is recorded as configured; this does not pin its underlying version or implement model continuity/checkpoints. Provider processing/retention policies still apply even where API storage is disabled.

## Usage and interrupted requests

Defaults are 20 external attempts and $1 of conservative reservations per workspace per UTC day, shared across providers, with 40,000 input bytes, 1,500 output tokens and a 30-second timeout. Model input/output prices must be configured explicitly. Reservations use input UTF-8 bytes plus 12,000 bytes of system/schema allowance and the output cap. They are deliberately conservative and retained in full after success or failure; displayed reserved dollars are not an invoice. Operator rates/model behavior may change, so provider-account spending caps are also needed. There is no automatic price discovery or fallback model.

Migration 0007 adds owner-scoped daily usage, durable provider invocations and run-to-invocation links without altering existing task tables. A quota reservation and `running` invocation commit before the network call, independently of application proposal writes. A completed result is cached and validated again on replay. Failed attempts replay their saved failure. Concurrent or interrupted running attempts return an uncertain-result conflict instead of issuing another network call. A lost application save can reuse the cached result without another reservation. A changed task snapshot, model, provider, upstream or prompt fingerprint rejects that reuse; old output cannot be rebased onto a newer task version. A deliberate new request uses a new key, fresh consent and may cost again.

Run attribution records provider, configured model/upstream, reported token usage when available and the full reservation. Original source/history and generated output remain local application records with existing retention limitations; production encryption, deletion, operational access and regional processing policy remain release gates.

## Evidence and limits

The provider-contract tests use synthetic HTTP transports for all six native request/response formats. PostgreSQL concurrency tests cover shared quota reservations; rollback/replay, invalid output, timeout, errors, foreign access and stale-task behavior are covered. Browser tests exercise consent reset, provider attribution through approval, fixed task scope and lost-reply replay. This validates the application boundary, not live vendor accounts or real model quality. Real acceptance requires operator-supplied keys, compatible model IDs, current rates and consented synthetic requests.
