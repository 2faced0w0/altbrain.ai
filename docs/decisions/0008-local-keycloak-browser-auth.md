# Local Keycloak browser authentication and invitations

Accepted locally, 26 October 2026. The user selected local Keycloak first and chose `user1@altbrain.ai` for the initial invitation. No external identity account or email delivery was provisioned.

Keycloak 26.8.1 handles registration, passwords, brute-force protection, email verification, recovery and provider logout. Mailpit v1.31.3 captures local SMTP without a host SMTP port or external relay. Web/admin/inbox ports bind only to loopback. Provider account data has a separate persistent development volume; Workroom uses its existing PostgreSQL DB. Random client/admin credentials live only in ignored .local/auth files. Realm imports never overwrite an existing realm on startup.

A confidential server client uses authorization code + S256 PKCE, random browser-bound state and nonce. Transactions expire after ten minutes and are atomically consumed before exchange. ID tokens require RS256, exact issuer/client audience, expiry, issued-at, subject, verified email and matching nonce; authorized-party checks cover multiple audiences. Provider tokens and refresh tokens are discarded, never put into SPA storage or the application database. Callback query strings are redacted from Uvicorn access logs, and callback redirects use a fixed configured app origin plus a bounded internal path.

The app session is a high-entropy opaque cookie. Only its SHA-256 hash, issuer, minimal verified claims, CSRF token and bounded expiry are persisted. Cookies are HttpOnly, SameSite=Lax, host-only, /api scoped, and Secure outside local/test or over HTTPS. Browser mutations require both the configured Origin and the unpredictable CSRF header. Existing signed bearer clients remain supported and retain strict JWT validation. New browser-auth identities qualify subjects with an issuer hash; accounts are never linked by a caller-supplied email or to the existing demo identity. Owner/membership queries still scope every owned resource.

Login rotates the old browser session. Expiry is the ID-token expiry capped at one hour; the supplied local realm uses fifteen minutes. There is no silent refresh or long-lived refresh token storage. Logout deletes the current application session immediately, clears its cookie and owner-scoped browser draft backups, then continues through the provider's logout confirmation. Password reset/provider revocation on other devices does not currently invalidate an already issued Workroom session until that session expires. This bound is explicit; back-channel/global revocation is required before external beta.

A verified account needs a one-use, matching-email invitation before a workspace is created. Existing atomic invitation consume/user/workspace/membership behavior is retained. Login attempts are rate-limited per observed client address and redemption attempts per qualified identity, in expiring database windows committed even when redemption fails. Operator-only issuance needs database access and prints a private code-file path, not its token; raw codes live in ignored files with an explicit expiry. No public invitation-issuance API or email-as-authorization shortcut was introduced.

Real provider acceptance runs against a unique disposable realm and database on separate ports. It registers a synthetic account, verifies mail through Mailpit, sets its initial password (Keycloak's current email-first flow), redeems an invite, persists a task, logs out and recovers the account. It removes only the recorded test realm at teardown. The main Workroom realm and existing tracker data stay untouched. Personal password entry remains the user's own action in Keycloak.

Production release still requires Keycloak production mode and database, TLS/hostnames/proxy trust, restricted application DB roles/RLS, real mail delivery, retention/backups, MFA/operator access, global revocation, monitoring and a security review. This local development stack is not a published secure external beta.
