# ADR 0004: durable mock capture and reviewed task creation

Accepted for the local M2 paste/review slice, 26 October 2026.

The Capture screen uses an explicitly labelled deterministic, rule-based mock. It makes no AI/provider calls, consumes no tokens, and has no credentials. It recognises simple imperative request lines, skips email header lines and quoted/signature trails, and produces at most 20 candidates from at most 20,000 source characters. This fixture demonstrates the workflow; it is not a general email-understanding model. Dates and priorities are not inferred. Ambiguous date phrases produce a clarification note; the user may choose a precise deadline or approve undated work.

Migration 0003 adds conversations, source messages, mock runs and proposals. Original messages and source hashes belong to the application. Extracted candidates must pass a strict schema and their evidence must occur literally in the source. Failures preserve a failed run, source and editable draft without any task effect. Capture output cannot supply workspace IDs or authoritative task IDs. A provider protocol allows future adapters; no live adapter is enabled.

Proposals have separate editable task fields, immutable extraction evidence, a review version, review state and an approved task reference. Save edits does not create a task. Approve creates the task, source-bearing activity event, proposal review and retry receipt in a single transaction. Optimistic proposal version checks roll back losing concurrent approvals, including any tentative task/event inserts. Repeated approval of the same fields returns the original commit; conflicting post-review edits fail. Reject records review only. All reads/writes derive workspace from the existing verified owner boundary and use composite foreign keys to prevent cross-workspace linkage.

Conversation draft autosaving is versioned. A browser backup keyed by owner and conversation recovers text on refresh; it contains draft text, never API/session keys. A backup that differs from a newer server revision pauses automatic saving until an explicit user action. Browser storage can be unavailable or cleared, so acknowledged server saves are the durable record. Uncertain network writes retain the original payload/version/key for retry; autosaving cannot replace a pending capture retry. A failed history refresh after an acknowledged capture is not treated as an uncommitted write.

Conversation history loads 50 messages per page with a Load older action. Task detail shows approved evidence and links back to the original conversation. User source text is rendered as text, not executable markup or tool instructions. Files, live providers, BYOK, task-scoped guidance/update proposals, summaries/retrieval, streaming/failover and beta release hardening remain separate milestones.
